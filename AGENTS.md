# Audio-Birdle Project Overview

Context for AI agents working on this project.

## Project Overview

Audio-Birdle is a web-based bird identification game inspired by Wordle. Players listen to bird songs and guess the correct bird species. Features:

- **Normal Mode:** Multiple choice (4 options) with 4 guesses
- **Hard Mode:** Free-text input with autocomplete, 6 guesses, taxonomic hints
- **Practice Mode:** Unlimited free-play with the full bird list for the selected region
  Data is generated by Python scripts that process eBird API data.

## Tech Stack

- **Frontend:** React ^19.2.x, Vite ^8, Tailwind CSS 4.x, zustand 5, lucide-react (icons), sonner (toasts)
- **Backend (scripts):** Python 3.x with pandas, requests, beautifulsoup4, selenium
- **Data Source:** eBird API for bird observations and audio
- **Testing:** Vitest 4 (JavaScript), pytest (Python)
- **Linting:** ESLint (JS), pylint (Python)
- **CI/CD:** GitHub Actions with smart test selection
- **Hosting:** Cloudflare Pages (auto-build from main)

### Canonical Hash Algorithm

**Critical:** The hash implementation MUST be identical in Python and JavaScript. Any changes to the algorithm require updating both implementations and all tests.

**Algorithm Details:**

- **Name:** DJB2 hash (variant)
- **Formula:** `hash = ((hash << 5) - hash) + char_code`
- **Salt:** `"birdle-salt-2025"` (appended to bird ID)
- **Output:** 32-bit unsigned integer formatted as 8-character lowercase hex string
- **Example:** `hashBirdId("amerob")` → `"104c723e"`

**Implementations:**

- **JavaScript:** [src/utils/HashUtils.jsx](src/utils/HashUtils.jsx) - `hashString()` function
- **Python:** [scripts/generate-daily-birds.py](scripts/generate-daily-birds.py) - `hash_bird_id()` function

**Key Requirements:**

1. **Zero-padding:** Hashes must always be exactly 8 characters (e.g., `"0391253f"`, not `"391253f"`)
2. **Lowercase:** Hashes must be lowercase hexadecimal
3. **Deterministic:** Same input must always produce same output
4. **Consistent:** Python and JavaScript must produce identical output for same input

**Data Pipeline:**

```
Python Script (generate-daily-birds.py)
  → hash_bird_id(birdId)
  → daily.json { answerHash: "8charhex" }
  → Frontend (DailyBirdUtils.jsx)
  → hashBirdId(birdId) for lookup
  → findBirdByHash() matches bird
```

**Testing:**

- JavaScript: [tests/unit/utils/HashUtils.test.jsx](tests/unit/utils/HashUtils.test.jsx) and [tests/integration/hash-consistency.test.js](tests/integration/hash-consistency.test.js)
- Python: [tests/test_generate_daily_birds.py](tests/test_generate_daily_birds.py) hash tests
- Both verify identical output for test vectors (e.g. `amerob` → `104c723e`)

**Warning:** Never change the hash algorithm without:

1. Updating both Python and JavaScript implementations
2. Updating all test expectations
3. Creating a migration strategy for existing daily.json data
4. Ensuring backward compatibility or data migration

### Common Utilities

**StorageUtils** - Unified localStorage operations with error handling:

```javascript
import {
  getStorage,
  setStorage,
  removeStorage,
  isStorageAvailable,
} from "./utils/StorageUtils";

// Check if localStorage is available
if (isStorageAvailable()) {
  // Get data with default value
  const gameState = getStorage("audio-birdle-game-state", null);

  // Set data (automatically stringified)
  setStorage("audio-birdle-game-state", { guesses: [], won: true });

  // Remove data
  removeStorage("audio-birdle-game-state");
}
```

**RetryUtils** - Network operations with automatic retry:

```javascript
import { fetchWithRetry, retryWithBackoff } from "./utils/RetryUtils";

// Fetch with retry (3 attempts, exponential backoff)
const response = await fetchWithRetry(
  "/data/birds.json",
  {},
  { maxRetries: 3, baseDelay: 1000 },
);
const data = await response.json();

// Retry any async operation
const result = await retryWithBackoff(
  async () => {
    const data = await someAsyncOperation();
    if (!data) throw new Error("No data");
    return data;
  },
  { maxRetries: 2, baseDelay: 500, context: "data-fetch" },
);
```

**HashUtils** - Canonical hash implementation (matches Python):

```javascript
import { hashString } from "./utils/HashUtils";

// Generate 8-character hex hash (matches Python implementation)
const birdHash = hashString("American Robin");
// Returns: 'a1b2c3d4' (8-char hex string)
```

**Important:** Hash algorithm is canonical across Python and JavaScript. Both use same salt "birdle-salt-2025". DO NOT modify the hash implementation without updating both languages.

## Development Workflow

### When Adding New Features

1. **Network Operations:** Always use RetryUtils for fetch calls. Don't implement custom retry logic.

   ```javascript
   import { fetchWithRetry } from "./utils/RetryUtils";
   const response = await fetchWithRetry("/data/file.json");
   ```

2. **Storage Operations:** Always use StorageUtils for localStorage. Don't use localStorage directly.

   ```javascript
   import { getStorage, setStorage } from "./utils/StorageUtils";
   const data = getStorage("key", defaultValue);
   setStorage("key", data);
   ```

3. **Hash Operations:** Use HashUtils.hashString() for consistent bird ID hashing. Don't implement custom hash.

### Testing Strategy

**JavaScript Tests (Vitest):**

- Locations: `tests/unit/` (unit) and `tests/integration/` (integration)
- Environment: jsdom with mocks (localStorage, Audio, matchMedia, fetch)
- Coverage threshold: per-file 70% lines / 70% functions / 65% branches / 70% statements on `src/utils/**/*.jsx`, `src/stores/**/*.ts` and `src/App.jsx` (see vitest.config.js)
- Test sharding: 3 shards for `tests/unit` in CI
- Suite size: 584 JS tests (429 unit + 155 integration)

**Python Tests (pytest):**

- Location: `tests/`
- Fixtures: Sample taxonomy, birds, regions data
- Coverage threshold: 70% on `scripts/` (pyproject.toml)
- Suite size: 104 tests

### Smart Test Selection

The [smart-test.yml](.github/workflows/smart-test.yml) workflow intelligently runs tests based on commit patterns. On PRs the analyzer reads the PR head commit (not the synthetic merge-ref commit):

| Commit Pattern                     | Tests Run                                                               |
| ---------------------------------- | ----------------------------------------------------------------------- |
| `Update challenge:`                | Game logic tests only (GameLogic, DailyBirdUtils, generate-daily-birds) |
| `Update dependency ...` (Renovate) | Dependency resolution + lint + build verification                       |
| `chore(deps):`                     | Dependency resolution + lint + build verification                       |
| `fix:`                             | Affected area tests = integration tests + build verification            |
| `feat:`                            | Full test suite (integration + build)                                   |
| `chore:`                           | Minimal (lint only)                                                     |
| `Merge ...` / other                | Standard (build verification)                                           |
| JS files changed                   | JS unit tests (sharded parallel)                                        |
| Python files changed               | Python unit tests                                                       |

## Important Notes

- **Utility Usage:** Use RetryUtils for all network operations (don't implement custom retry logic). Use StorageUtils for all localStorage access (includes error handling and QuotaExceededError detection).
- **Hash Consistency:** Python and JavaScript use identical hashing algorithm (same salt: "birdle-salt-2025"). DO NOT modify hash implementation without updating both languages.
- **State Migration:** Game state supports automatic migration from legacy formats (v0 single-store and v1 multi-store) to version 2; legacy keys are removed after import.
- **Multi-Region:** Each region-date-mode combination is independent (e.g., "us-2025-12-27-normal", "eu-2025-12-27-hard")
- **Deterministic:** Answer options generated with seeded randomness for consistency
- **Daily Updates:** Automated via GitHub Actions at 4 AM UTC (cron: '0 4 \* \* \*'); data commits to main trigger the Cloudflare Pages auto-build
- **API Key:** eBird API key stored in EBIRD_API_KEY environment variable
- **Data Files:** public/data/\*.json are generated by Python scripts, not hand-edited
- **Pre-commit Hooks:** Runs gitleaks (secret scanning), ESLint, pylint (--errors-only) before commits

## Security & Best Practices

- **Path Traversal Prevention:** Validate file paths, prevent directory traversal
- **Secret Scanning:** gitleaks in pre-commit hooks
- **Dependency Security:** Automated dependency review via GitHub Actions
- **Code Quality:** ESLint (JS) and pylint (Python) enforce standards
- **Security Headers:** CSP, X-Content-Type-Options, Referrer-Policy, X-Frame-Options, Permissions-Policy served via Cloudflare Pages `public/_headers`
- **Hardened Runners:** All CI workflows run step-security/harden-runner with blocked egress allowlists (except daily-update.yml, which audits by design)
- **Error Handling:** Graceful degradation (fallback to hash-based selection if daily.json unavailable)
- **State Validation:** Ensure game state format, migrate old formats automatically
