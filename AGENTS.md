# Audio-Birdle Project Overview

Context for AI agents working on this project.

## Project Overview

Audio-Birdle is a web-based bird identification game inspired by Wordle. Players listen to bird songs and guess the correct bird species. Features:
- **Normal Mode:** Multiple choice (4 options) with 4 guesses
- **Hard Mode:** Free-text input with autocomplete, 6 guesses, taxonomic hints
- **Practice Mode:** Unlimited free-play with full bird list
Data is generated by Python scripts that process eBird API data.

## Tech Stack

- **Frontend:** React 19.1.0, Vite 6.4.1, Tailwind CSS 3.4.17
- **Backend (scripts):** Python 3.x with pandas, requests, beautifulsoup4, selenium
- **Data Source:** eBird API for bird observations and audio
- **Testing:** Vitest (JavaScript), pytest (Python)
- **Linting:** ESLint (JS), pylint (Python)
- **CI/CD:** GitHub Actions with smart test selection
- **Hosting:** Cloudflare Workers (wrangler.jsonc)

## Architecture

### Frontend (React/Vite)

**Core Game Logic ([src/utils/GameLogic.jsx](src/utils/GameLogic.jsx))**
- Multi-region, multi-date game state management
- State migration support (version 2 format)
- Guess processing with statistics tracking
- Region-specific and global stats
- Deterministic answer option generation with seeded randomness

**Daily Bird System ([src/utils/DailyBirdUtils.jsx](src/utils/DailyBirdUtils.jsx))**
- Hash-based bird ID hashing (8-char hex)
- Daily.json loading and validation
- Hash-based bird lookup
- Fallback to hash-based selection if daily.json unavailable

**Data Management:**
- [StorageUtils.jsx](src/utils/StorageUtils.jsx) - LocalStorage wrapper with error handling
- [LoadGameData.jsx](src/utils/LoadGameData.jsx) - Fetch JSON data from `/data/`
- [HashUtils.jsx](src/utils/HashUtils.jsx) - String hashing utilities

### Python Data Processing Scripts

**Critical Scripts:**
1. **generate-daily-birds.py** - Generates daily bird answers ensuring no repeats within X days
   - Hash-based bird ID generation (matches JS implementation)
   - Recent answer tracking to prevent duplicates
   - Subregion-aware selection
   - Daily.json and history.json generation

2. **game-data-generator.py** - Creates bird data JSON from taxonomy and URLs
   - Processes eBird taxonomy data
   - Groups audio URLs by species code
   - Filters birds without audio
   - Family name formatting

3. **generate-daily-region-data.py** - Fetches eBird observations for regions
   - API integration with eBird v2 API
   - Subregion selection
   - Species code extraction and deduplication

### Game Configuration ([Constants.jsx](src/utils/Constants.jsx))

```javascript

HARD_MODE_HINT_TIMING: { ORDER: 1, FAMILY: 3, GENUS: 5 }  // Progressive hints

```

### Game Modes

**Normal Mode:**
- 4 multiple choice options
- 4 guesses
- Basic correct/incorrect feedback

**Hard Mode ([TaxonomyUtils.jsx](src/utils/TaxonomyUtils.jsx), [HardModeGame.jsx](src/utils/HardModeGame.jsx)):**
- Free-text input with fuzzy autocomplete
- 6 guesses
- Progressive taxonomic hints (Order → Family → Genus)
- Immediate feedback showing which taxonomic levels match
- Separate state/storage from normal mode

**Practice Mode ([PracticeGame.jsx](src/utils/PracticeGame.jsx)):**
- Unlimited rounds
- Same mechanics as normal mode
- No persistence


### Testing Strategy

**JavaScript Tests (Vitest):**
- Location: `tests/unit/utils/`
- Environment: jsdom with mocks (localStorage, Audio, matchMedia, fetch)
- Coverage threshold: 70% (critical files: 80-85%)
- Test sharding: 3 shards for parallel execution

**Python Tests (pytest):**
- Location: `tests/`
- Fixtures: Sample taxonomy, birds, regions data
- Coverage threshold: 70%
- Markers: unit, integration, slow, network

### Smart Test Selection

The [smart-test.yml](.github/workflows/smart-test.yml) workflow intelligently runs tests based on commit patterns:

| Commit Pattern | Tests Run |
|---------------|-----------|
| `Update challenge:` | Game logic tests only (GameLogic, DailyBirdUtils, generate-daily-birds) |
| `chore(deps):` | Lint + build verification |
| `fix:` | Affected area tests + integration tests |
| `feat:` | Full test suite |
| `chore:` | Minimal (lint only) |
| JS files changed | JS unit tests (sharded parallel) |
| Python files changed | Python unit tests |

## Important Notes

- **Hash Consistency:** Python and JavaScript use identical hashing algorithm (same salt: "birdle-salt-2025")
- **State Migration:** Game state supports automatic migration from old format to version 2
- **Multi-Region:** Each region-date combination is independent (e.g., "us-2025-12-27", "eu-2025-12-27")
- **Deterministic:** Answer options generated with seeded randomness for consistency
- **Daily Updates:** Automated via GitHub Actions at 4 AM UTC (cron: '0 4 * * *')
- **API Key:** eBird API key stored in EBIRD_API_KEY environment variable
- **Data Files:** public/data/*.json are generated by Python scripts, not hand-edited
- **Pre-commit Hooks:** Runs gitleaks (secret scanning), ESLint, pylint before commits

## Commit Message Conventions

The smart-test workflow parses commit messages to determine which tests to run:

- `Update challenge: [timestamp]` - Daily data update
- `feat: [description]` - New feature
- `fix: [description]` - Bug fix
- `chore(deps): update dependency [package] to [version]` - Dependency update
- `chore: [description]` - Other maintenance

## Security & Best Practices

- **Path Traversal Prevention:** Validate file paths, prevent directory traversal
- **Secret Scanning:** gitleaks in pre-commit hooks
- **Dependency Security:** Automated dependency review via GitHub Actions
- **Code Quality:** ESLint (JS) and pylint (Python) enforce standards
- **Error Handling:** Graceful degradation (fallback to hash-based selection if daily.json unavailable)
- **State Validation:** Ensure game state format, migrate old formats automatically
