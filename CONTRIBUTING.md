# Contributing to Audio Birdle

Thanks for helping improve **Audio Birdle**!

## Report a bug or suggest a feature

Open an issue with:

- What you expected to happen.
- What actually happened.
- Steps to reproduce (browser, OS, region, mode).
- A screenshot or recording if useful.

Please check for duplicates first.

## Make a pull request

1. Fork the repository and create a branch.
2. Install the development tools:

   ```bash
   python -m venv .venv
   source .venv/bin/activate
   pip install -r requirements-dev.txt
   npm ci
   python -m playwright install chromium
   ```

3. Make the change.
4. Run the relevant checks:

   ```bash
   make lint
   make test-python
   make test-js
   make test-e2e
   ```

5. Commit with a descriptive message and open a pull request.

### Code style

- **HTML** lives in `sitegen/templates/` (Jinja). Do not put HTML strings in
  Python.
- **CSS** lives in `sitegen/static/css/`; keep it mobile-first and lint-clean.
- **JavaScript** lives in `sitegen/static/js/`; use ES modules and keep page
  entry points small. Shared logic belongs in `core/` or `ui/`.
- Use `textContent` for data-derived UI text. Do not use `innerHTML`.
- Reuse the warm paper / pixel-nature tokens in
  `sitegen/static/css/tokens.css`; avoid introducing ad-hoc fonts or colours.
  The VT323 font and SVG scene art are vendored and documented in
  `THIRD_PARTY_NOTICES.md`.
- Add tests for behavior changes. Browser flows belong in `tests/e2e/`.
- Avoid large unrelated changes in one pull request.

### Data and cache safety

`public/data` is generated by the Python pipeline. Do not hand-edit it. If you
change a data file manually for a test, regenerate the manifest:

```bash
python -m sitegen manifest --data-dir public/data
```

Never remove the manifest or the hash verification in
`sitegen/static/js/core/data.js`; they prevent Cloudflare/browser caches from
mixing old and new data.
