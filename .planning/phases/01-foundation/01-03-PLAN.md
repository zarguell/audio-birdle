# Refactoring Safety Checklist

Use this checklist for every refactored area to ensure safe, incremental changes without breaking existing functionality.

## File Change Verification

Before marking any refactored area complete, verify:

- [ ] All modified files compile/build without errors
- [ ] No runtime errors in browser console
- [ ] TypeScript/linting passes (or errors documented)
- [ ] Code follows existing project conventions

## Test Validation

For each refactored module, ensure:

- [ ] All existing tests continue to pass
- [ ] No new test failures introduced
- [ ] Edge cases are covered (null, undefined, errors)
- [ ] Integration tests pass (if applicable)

## State Migration Compatibility

For state management changes, ensure:

- [ ] Existing localStorage data can be migrated
- [ ] Old game state format handled gracefully
- [ ] No data loss for existing users
- [ ] Migration tested with sample data

## localStorage Data Preservation

When modifying storage-related code, verify:

- [ ] Reading/writing to localStorage still works
- [ ] Existing keys are preserved
- [ ] No accidental key deletions
- [ ] Storage quota handling is preserved

## Audio Playback Integrity

For audio-related changes, ensure:

- [ ] Audio playback still works across browsers
- [ ] Dead URL tracking is maintained
- [ ] Audio caching still functions
- [ ] Play/pause/stop controls work correctly
- [ ] Error handling for audio failures is preserved

## Visual Component Behavior

For UI component changes, verify:

- [ ] Visual appearance unchanged (unless intentional)
- [ ] All user interactions still work
- [ ] Responsive layout maintained
- [ ] Accessibility features preserved
- [ ] No console errors or warnings

## Performance Considerations

Before completing refactor, check:

- [ ] No performance regression
- [ ] No unnecessary re-renders
- [ ] No memory leaks
- [ ] Bundle size acceptable (if frontend bundle)

## Rollback Plan

If issues are discovered, ensure:

- [ ] Git commit is atomic (can revert cleanly)
- [ ] Rollback steps are documented
- [ ] No manual data cleanup required for users

## Sign-off Requirements

Before marking refactoring complete:

- [ ] All checklist items above pass
- [ ] No blocking issues discovered
- [ ] Manual testing completed (if applicable)
- [ ] Ready to merge to main branch
